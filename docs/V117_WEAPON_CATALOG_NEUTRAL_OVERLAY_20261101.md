# 武器数据库：v1.17 版本化 +0 来源覆盖与差异核对（2026-11-01）

## 用户决定的最终验收基准

**Tarnished.dev 公共 v1.17 网站的可操作功能与同条件数值**。无需实机、游戏菜单截图、官方最新 Regulation 客户端认证。本项目独立实现、不复制竞品私有前端/数据。对比同一个版本、同一个武器/质变/强化和玩家属性，才可能确认 AR 数值对等。

- [50/50 组真实竞品网页 AR 对照通过](./TARNISHED_DEV_50_CASE_PARITY_20261031.md)，两轮各 50 项独立输入核对且最终误差零。这不是 487 条全部经过竞品网页独立数值观察。
- 固定公开来源：`ThomasJClark/elden-ring-weapon-calculator` v1.17 pinned commit `3539d87e446f3b9d5b94157f8a2023e28ffea7d2` 的 JSON 参数。这个来源**不是 Tarnished.dev 私有数据源**；其数值仅属于独立的有版本公开来源证据，不能冒充 Tarnished.dev 的每项实测。

## 本次交付：用户主动读取、严格分离主数据

`/weapon-database/` 增加 **Load pinned public v1.17 source** 按钮，只有点击才请求公开 JSON（独立网络请求，不计入静态部署成本）。严格校验 JSON 的 3,296 个变体后，只选择同名且**唯一**的默认 Standard / None 变体。带入原始物理／魔力／火焰／雷电／圣属性攻击与准确 +0 reinforcement 倍率，分别得到 +0 **基础攻击**五元组；另显示 STR/DEX/INT/FAI/ARC 最低需求。

这是**独立对照视图**而不是修改数据文件：

- 72 条原主目录 **+0 攻击 / 重量缺失**的记录可以看到单独标记的 *pinned v1.17 +0 reference* 值。原 canonical `attack=null`、`weight=null` 不被填充，更不推定装备负重。
- 对明确标记社区来源分歧的武器，v1.17 来源与社区的攻击/属性要求逐字段并列；若攻击值/要求一致，也保留社区分歧标记。特别是重量冲突**无法依靠此来源消除**，因为数据来源未提供可靠重量。
- 对未事先标为争议但出现的新攻击或属性要求差异，仍明确显示而非静默通过。无源项、多个中性变体和缺失倍率被标为未知并拒绝填值。
- 原过滤、排序、数值字段、装备重量/roll 计算、Build Planner 和现有来源页面**全部保持原有的保守行为**；页面对照的字符串不会被上传至本网站服务端。外部 GitHub 下载仍会向其服务器发起用户主动请求。
- 保留脚本级静态真相：`npm run audit:weapon-parity` 的 72 / 9 原始社区事实缺口保持未关闭。这与“新增 v1.17 source-only 对照视图”不矛盾。验收 #83 / #86 不因页面数量增长而自动关闭。

## 真实固定来源审计结果

GitHub Actions [v1.17 pinned 数学审计](https://github.com/garrison2025/Elden-Ring/actions/runs/41249556281) 对完整 3,296 变体的固定来源进行校验后，报告：

| 指标 | 实际观察 |
|---|---:|
| 本地目录与 v1.17 中性来源精确一对一匹配 | **487 / 487** |
| 原来主字段 +0 攻击／重量未知、现在可看 v1.17 攻击来源参考 | **72 / 72** |
| 原目录有显式来源争议旗标，且能映射到 v1.17 | **9 / 9** |
| 社区 +0 基础攻击与 pinned v1.17 不同 | **41 条** |
| 社区最低属性要求与 pinned v1.17 不同 | **25 条** |
| 不可匹配／中性变体不唯一／数据不完整 | **0** |
| 被来源提供的可采信装备重量 | **0** |

攻击与需求差异**可能落在同一武器上**，不可把 41 与 25 直接相加宣称 66 把不同武器。差异有可能来自网站版本、历史更新、社区来源口径，不能把出现差异自动等同于“社区错误”。新增的用户筛选器分别显示 72 个原始缺口、9 个既有争议、41 条攻击差异、25 条需求差异，以及两项差异的去重合集。

这证明的是**全部 487 个名称的公开 v1.17 source-to-source 数据可读性**，不是 487/487 Tarnished.dev 网站单武器 AR 结果验收；单个实际竞品网页对标的严格完成证据仍只有此前 50 个同条件 AR 测试。

## 验证标准

- 单元测试覆盖按名称归并、普通/特殊武器中性变体选择、+0 倍率、单字段攻击和需求差异、用户原始资料不被篡改、重量未知、无效和重复来源。
- 在 `scripts/audit-v117-pinned.mjs` 的原有真实来源 CI 中统计映射总数、72-source-only 和分歧覆盖；只输出汇总、不导出第三方完整原始参数。
- 外部浏览器的 `RUN_REAL_V117_BROWSER=1` 路径必须由真实用户事件点击加载，验证 Albinauric Shield 的来源 +0 Physical 78、72 项独立对照都可用，原重量仍不明。
- 如源数据或名字发生变化，测试应报错、浏览器显示不可用，不能暗中生成不存在的事实。
